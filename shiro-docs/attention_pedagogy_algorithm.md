# The Shiro Algorithm: Balancing Delivery, Attention, and Pedagogy

To build a feed algorithm that rivals TikTok in engagement while maintaining mathematically rigorous educational overlap, we are moving beyond standard recommender systems. 

TikTok uses a Deep Learning Recommendation Model (DLRM) designed to maximize a single scalar: **Time-in-App**. 
Shiro must optimize a multi-objective reinforcement learning function: **Time-in-App** AND **Knowledge Retention**.

Crucially, as you stated, **User A and User B are fundamentally different**. The algorithm must deliver the exact same baseline knowledge through completely distinct presentation wrappers depending on their cognitive profiles.

Below is the theoretical research and breakdown of how to structure this algorithm.

---

## 1. The Personalization Vector (Understanding User A vs. User B)

Before the algorithm chooses a video or interaction, it must mathematically map the user. We must expand the user embedding beyond standard metrics (age, topic interests).

**The Shiro Cognitive Profile Embedding:**
1. **Frustration Tolerance (0.0 - 1.0):** How many "wrong answers" or complex concepts can this user absorb before swiping away? 
2. **Attentional Cadence:** Do they prefer 3-minute deep dives (User A) or 15-second rapid micro-lessons (User B)?
3. **Modal Preference:** Do they learn better visually (animations), textually (overlays), or kinesthetically (interactive games)?
4. **Current Decay State:** A real-time matrix of everything the user has watched and where those concepts sit on their unique forgetting curve.

## 2. The Presentation & Delivery Matrix

The genius of your "Aggregator + Overlay" model is that the *content* (the YouTube video) is separated from the *delivery* (the interactive wrapper). 

For the exact same concept (e.g., 'Gravity'), the algorithm dynamically wraps the presentation based on the user:

*   **User A (High Frustration Tolerance, Detailed Thinker):**
    *   *Delivery:* A 4-minute continuous video.
    *   *Overlay:* No interruptions. At the very end, a high-friction, open-ended question generated by the LLM requiring synthesis.
*   **User B (Low Attention Span, Needs Constant Serotonin):**
    *   *Delivery:* The same 4-minute video, but chopped into 30-second segments.
    *   *Overlay:* After every 30 seconds, the video pauses. A playful, Tinder-style "Swipe True or False" game appears. If they get it right, confetti explodes, triggering a dopamine hit, and the video resumes.

*The algorithm's core task is selecting the wrapper, not just the content.*

## 3. The Core Algorithm: Constrained Reinforcement Learning

To crack this, we treat the feed as a **Contextual Multi-Armed Bandit** or an **RL (Reinforcement Learning) agent**.

### The Objective Function
The engine calculates a score for every possible next item in the user's feed.

`Score(Item) = ( α × Engagement_Prediction ) + ( β × Pedagogical_Necessity )`

*   **Engagement Prediction:** How likely are they to watch 100% of this and not close the app? (Calculated by matching the item's format against the user's Attention Cadence).
*   **Pedagogical Necessity:** How desperately does the user need to review this concept before they forget it forever? (Calculated via the FSRS / SM-2 spaced repetition formula).

### The Dynamic Weights (α and β)
The weights `α` (Entertainment) and `β` (Education) are not static. The algorithm dynamically shifts them *while the user is scrolling*.

*   **Minute 1-3:** The user just opened the app. They are bored. The algorithm sets `α = 0.9` and `β = 0.1`. It serves highly visually stimulating, novel videos (TikTok mode) to lock them into the trance.
*   **Minute 4-10 (The Trance State):** The user is hooked. The algorithm stealthily flips the weights. `α = 0.4`, `β = 0.6`. It begins injecting high-friction interactive games and spaced repetition reviews. Because they are in a flow state, they tolerate the friction. 
*   **The Churn Signal:** If the user hesitates, skips a video in under 2 seconds, or gets frustrated by a game, the algorithm detects a "Churn Risk." It immediately flips back to `α = 0.9` and serves "Sugar" (an incredibly easy, highly entertaining video) to reset their dopamine baseline.

## 4. Engineering the "Learning Overlap" (The Concept Threading)

You cannot have a random feed in education. Concepts must overlap. We achieve this using a hidden **Curriculum Graph Tracker**.

1.  **Tagging:** Every 30-second video snippet in the massive localized database is tagged with overlapping `Concepts`. (Video 1 = `[Gravity, Mass]`, Video 2 = `[Mass, Momentum]`).
2.  **The Overlap Constraint:** The algorithm is mathematically constrained so that **Video N+3 must contain at least one conceptual tag from Video N.**
3.  **The "Aha!" Moment:** By threading concepts, the user watches disjointed, seemingly random entertaining videos. However, because the algorithm quietly overlapping `Mass` across three different videos (one about Planets, one about Car Crashes, one about Black Holes), the user's brain synthesizes a massive, generalized understanding of `Mass` without realizing they were being taught a curriculum.

## 5. Next Steps for Implementation
To build this practically, we don't need to invent a new breed of AI. We can execute this using established architecture:
1.  **The Local State Machine:** Use React Native to build a dynamic overlay engine. It can render a "Video Mode" or an "Interactive Mode" over the exact same URL.
2.  **The Headless Rules Engine:** Before building a true ML ranker, we build a heuristic rules engine. If `Consecutive_Watch_Time > 5 mins` -> `Inject Review Game`. If `Skip_Rate_Last_3_Videos > 50%` -> `Inject Low-Friction Video`.
3.  **Telemetry Gathering:** The app begins anonymously gathering the exact data needed to train the full ML model (swipe speed, hesitation on interactive overlays, preferred delivery modes for User A vs User B).
